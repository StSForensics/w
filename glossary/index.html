Glossary: declared scope, independent source, declared gap

These are the terms the O4M Record Tests use, in plain words. Each one comes from the published draft.

Declared scope

The actions, systems and time span the operator says its record is meant to cover, written down and sealed before the first event (requirement C1). Every result prints the scope it was checked against. Completeness is only ever measured inside it.

Independent source

A record the operator does not control, such as a payment processor's record of an effect, a provider's usage figures, or a physical sensor. It counts as independent only if the checker gets it from whoever produced it, or it carries that producer's signature under a key the operator does not hold. A copy inside the operator's own export is labelled unverified.

Declared gap and undeclared gap

A declared gap is a period, event type, channel or field the operator says it does not capture. It is reported as a declared gap, never as a pass. A gap the checker finds that was not declared is an undeclared gap, and it fails.

Profile

Because few organisations can meet every requirement, each result names a profile. W is for people using a vendor's admin export, F is for organisations running their own agents, and P would need providers to sign usage receipts.

HOLD

A result that is neither pass nor fail because something the test needs does not exist yet, such as an independent time stamp or a third-party count. A HOLD comes with reason codes that say what is missing.

Unaltered and complete

Two different questions. Unaltered is not the same as complete explains the difference with an example.
